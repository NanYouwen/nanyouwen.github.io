AI 如何协助阅读陌生项目

如果只看演示，很多 AI 功能都显得轻松；一旦放进真实工作，细节马上会一件件找上门。这篇记录的是“AI 如何协助阅读陌生项目”背后的一个小问题：先让 AI 生成入口、模块、数据流和疑点地图，再由人抽查。我不把它写成万能答案，只把自己会怎样观察、怎样动手、什么时候停下来留给人说明白。对正在尝试 Agent 的人来说，能说清楚边界，往往比多会一个名词更重要。

先把场景摆到桌面上

最容易被忽略的场景是：一上来就让 AI 改代码而不理解系统。在演示里，事情通常从一个干净的输入开始，工具也总能一次成功；真实环境却会有旧文件、半截信息、权限差异和临时变化。若不先承认这些摩擦，Agent 只会把不确定性藏到一段很顺滑的文字里，最后仍然需要人返工。

围绕“AI 如何协助阅读陌生项目”，我会先写三句话：这次任务要留下什么结果；哪些资料可以使用；哪些动作必须停下来问我。三句话写完后，再决定需不需要记忆、检索、工具调用或多个角色。这样做看似慢，却能把“让它帮忙”变成一件可观察的工作，而不是把希望寄托在一次漂亮回答上。

这个概念到底解决什么

把它讲得简单一点：先让 AI 生成入口、模块、数据流和疑点地图，再由人抽查。模型负责根据上下文提出判断，工具负责读取或改变外部世界，规则负责限制范围，人负责目标、授权和最终验收。四件事缺一不可。只有模型没有工具，它更像会说话的顾问；只有工具没有规则，自动化就可能变成一条没人看守的流水线。

针对“先让 AI 生成入口、模块、数据流和疑点地图，再由人抽查”，我会把任务拆成“输入—判断—动作—证据”四格。输入要注明来源和新鲜程度；判断要允许“不确定”；动作要写明权限和是否可撤回；证据则包括链接、文件名、日志或截图。任何一格说不清，都不适合马上扩大权限。尤其是涉及外发、删除、付款、身份和隐私时，宁可多一个确认点，也不要让系统替人猜。

一个可以复现的小练习

可以从一个半小时以内的小任务开始：把地图当导航，不把摘要当最终事实。第一轮只让 Agent 观察，要求它列出材料、计划和可能的风险；第二轮只允许它做不会改变外部状态的动作；第三轮才考虑执行，并在执行前把对象、影响和回退方式展示给人。每一轮都保存输入摘要、工具结果和人的决定。

我通常会给它这样的任务说明：

目标：交付一份可以核对的结果。
可用材料：只使用我列出的文件和链接。
不确定时：列出缺口，不要补写事实。
需要执行时：先说明动作、对象和影响，等待确认。
最终交付：结论、依据、未解决问题和下一步。

这个格式对“AI 如何协助阅读陌生项目”的好处不在于它很漂亮，而在于出了问题以后能回看。若结果不对，先问是资料错、判断错、工具错，还是验收条件没写清，而不是笼统地说“AI 不行”。小任务跑通几次后，再决定是否值得做成长期工作流。

把结果交给另一个人看

我很喜欢做一个不依赖现场解释的检查：把“把地图当导航，不把摘要当最终事实”的任务说明、最终结果和运行记录交给一个没有参与过程的人，请他只回答三个问题——他能不能看懂目标，能不能找到依据，能不能判断下一步该由谁负责。如果这三个问题中有一个答不上来，说明流程虽然跑完了，交接还没有完成。

另一个和“一上来就让 AI 改代码而不理解系统”有关的有用动作是故意放进一条不完整资料。例如缺一列、链接过期、文件名称相似，看看 Agent 是停下来指出缺口，还是自作聪明地把空白补上。后者在演示里常常显得“主动”，在真实工作里却可能制造一串很难追的错误。测试不需要很复杂，十几个来自日常的例子，已经比一条顺利的演示更接近实际。

如果“AI 如何协助阅读陌生项目”会被重复使用，我还会给它留一张“变更卡”：这次调整了什么，为什么调整，哪几条任务重新跑过，哪几条仍然未知。这样以后模型、工具、资料或权限发生变化时，不必从记忆里猜影响范围。可靠性不是一次配置出来的，它更像一份随着使用不断补充的工作笔记。

几个容易踩到的坑

第一，把“能生成”当成“能负责”。生成速度很快，责任不会因此转移。第二，把所有资料都塞进上下文，结果是重点被淹没，隐私也失去边界。第三，把重试写成无限循环；工具失败时，Agent 应该有次数上限、替代路径和求助出口。第四，把一条成功演示当作质量证明，真实评估至少要包含空输入、过期资料、权限不足和重复执行。对“AI 如何协助阅读陌生项目”来说，我还会把“一上来就让 AI 改代码而不理解系统”放进反例，而不是只测试顺利路径。

还有一个关于“AI 工程”的朴素提醒：不要为了使用某种架构而使用它。一个 Agent 加两三个清晰工具，往往比五个互相交接的角色更容易理解和维护。只有当职责确实不同、权限确实需要隔离、或者任务可以并行时，多角色才值得引入。

我会留下的检查表

  1. 结果是否可以被别人独立核对？本篇还要额外核对：把地图当导航，不把摘要当最终事实。
  2. Agent 看到和能够改变的范围是否是完成任务所需的最小集合？
  3. 哪一步可能造成不可逆影响，确认界面是否把影响说清楚？
  4. 失败时是重试、换路、暂停，还是直接交给人？
  5. 这次运行留下的记录，是否足以解释它为什么做出这个决定？

最后的一点克制

我并不希望 Agent 把人的每一分钟都填满。好的自动化应该让人更早看到关键问题，把时间还给判断、创作和关系；如果它只是把复制粘贴换成了持续检查，工具就没有真正帮上忙。对“AI 如何协助阅读陌生项目”最稳妥的做法，仍然是从小范围开始，用真实任务观察一段时间，再决定是否扩大权限。速度可以慢一点，边界要清楚一点，留下回头路，很多事情反而会走得更远。每次复盘时，我也会问自己：这次究竟省下了什么，又把什么责任留在了人手里。也可以把这个问题写进自己的工作日志，过一段时间回看，才知道工具究竟是在帮忙，还是只增加了另一层管理。
