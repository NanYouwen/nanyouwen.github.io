第一次给 Agent 写任务说明：像交接工作一样具体

“帮我把这些资料整理一下”看上去像一句很自然的话，但交给 Agent 后，往往会得到一份也很自然、却不一定有用的结果。它可能按自己的理解做成摘要，忽略你真正要比较的指标；也可能把不确定的地方补得很完整，让人误以为内容都来自原始资料。问题通常不在 Agent 不够聪明，而在任务说明里缺少了人类同事会追问的那些背景。

我把给 Agent 的任务说明当作一次小交接。你不需要写成长文，但应该让它知道：为什么做、手头有什么、哪些不能碰、结果长什么样、遇到不确定时怎么办。这样写的好处不只是提升一次回答的质量，还能让任务以后被别人复用。

五件最值得先写清的事

第一是目标。不要只说整理资料，而要说“为下周评审准备一张对比表，帮助团队决定是否继续试用”。目标决定它该保留什么、忽略什么。第二是输入。列出文件、链接、已有笔记、数据范围，最好说明哪些来源更可信。Agent 如果没有材料，就只能依赖常识补全。

第三是限制。例如不能上传外部服务、不得改动原文件、不能根据经验补造数字、只能在工作时间执行、不得给外部联系人发消息。限制不是给 Agent 增加障碍，而是在告诉它哪些边界不可跨越。第四是交付物。要 Markdown、表格、草稿、代码差异，还是一份待确认清单？给一个小样例通常比形容“简洁专业”更有效。

第五是确认点。什么情况下可以继续，什么情况下必须停下来问你？例如遇到缺失字段、来源相互矛盾、会覆盖已有文件、需要花钱或发送外部消息时，应该暂停。这是让 Agent 和人协作，而不是让它盲目执行的关键。

把模糊请求改写一遍

下面这句很常见：

帮我研究一下几个竞品，做个总结。

它可以改成：

阅读我提供的三个官网链接和两份 PDF，只比较定价、核心功能、数据导出限制和中文支持。输出一张 Markdown 表格，每个结论附来源链接；找不到的内容写“未找到”，不要推测。完成后再列出最多三项需要我确认的问题，不要对外注册账号或提交表单。

后一个版本没有使用任何神秘技巧，却把目标、材料、范围、格式、证据和停止条件放在了同一处。Agent 即使做错了，也更容易知道错在什么地方；人审核时也不用猜它是否越过了边界。

任务要能被检查

“写得有洞察”“做得好看”这类要求并非无效，但单独交给 Agent 时很难判断完成。可以把它们转成可检查的条件：至少列出三个差异；每个事实有来源；表格不超过八列；结尾给出推荐与反例；面向刚接触此领域的人，不使用未解释的缩写。检查条件不是限制创造力，而是给第一版一个落点。

如果任务很大，也不要一口气要求它完成。让 Agent 先复述理解和计划，再处理第一部分；确认方向后再继续。这样即使目标有偏差，也是在前十分钟发现，而不是等它处理完几十份文件后才推倒重来。

留下可复用的外壳

真正重复的工作，可以把任务说明做成模板：

每次只替换内容，不必从聊天框重新组织思路。随着使用次数增加，你会发现这份模板也在帮人理清工作本身。很多“AI 没做好”的任务，换成一位新同事也会问同样的问题。把交接写具体，既是与 Agent 协作的技巧，也是把自己的想法讲明白的练习。

在任务结束时，也让它自查一次

交付前可以要求 Agent 用很短的清单回顾：它使用了哪些材料，哪些结论有来源，哪些部分是推测，是否触发过需要人工确认的条件。这个自查不能替代人审核，却能把隐藏的不确定性提到台面上。对于需要引用、整理、分析的任务，尤其值得加上这一环。

人审核时也不用从头读完所有内容。可以先检查一两个最重要结论、一两个边界案例和所有标为“不确定”的项；若这些都可靠，再看格式和表达。这样的分工让 Agent 负责完成可重复的整理，人负责把注意力放在真正影响决定的地方。

随着任务越来越熟，模板可以变得更短，因为共同语言已经形成。但不要把缩短说明误解为取消边界。最值得保留的通常是输入范围、不能做什么和何时确认——它们决定了 Agent 是否能在效率之外，也保持让人安心的分寸。

任务说明也应该带版本

一份反复使用的 Agent 模板会慢慢演化。某次执行后发现需要补来源，下一次就把引用要求加进去；发现 Agent 常误解某个业务词，就在术语旁加一句解释。把这种修改写在模板里，比每次在聊天框临时补充可靠得多。必要时还可以保留版本号或修改日期，方便团队知道当前应该用哪一份。

不要害怕在任务开始前要求 Agent 复述理解。它花的几十秒通常比执行偏了以后重做省得多。复述中若发现它把目标、范围或交付格式理解错了，马上修正即可；若理解正确，也等于为后续执行留下一条清楚的记录。

写任务说明的目标不是把 Agent 变成只会照抄的机器，而是让它有足够清晰的空间去完成该完成的事，同时不把不该替人决定的事情偷偷替掉。

遇到长期任务时，还可以要求它在每个阶段都汇报当前进度、已用资料和下一步计划。阶段性汇报比一次性等待最终结果更适合协作：方向错了能及时纠正，材料不足也能早点补齐，而不是把问题留到最后一分钟。

任务说明越清楚，后续的追问就越有价值。人不再反复解释基础背景，而能把注意力放在真正需要判断的例外、风险和取舍上，这正是 Agent 最该帮忙腾出的空间。

一份好说明也要允许回答“不知道”。若材料里没有答案、术语有歧义或需要外部权限，就要求 Agent 列出缺口而不是补写想象内容。把停止条件提前写进任务，既能保护结果，也会让后续补资料的动作更具体。
